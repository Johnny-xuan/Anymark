# 通配符功能模拟测试说明

## 概述

`WildcardSimulation.test.ts` 是一个使用真实 AI API 测试通配符功能的模拟测试套件。它验证 Agent 在实际对话场景中使用通配符命令的能力。

## 测试场景

测试包含 6 个真实用户场景：

### 场景 1: 批量移动 React 书签
- **用户查询**: "把所有 React 开头的书签移到前端框架文件夹"
- **预期行为**: 
  - Agent 创建"前端框架"文件夹
  - 使用 `mv React-* 前端框架` 批量移动书签
  - 验证所有 React- 开头的书签已移动

### 场景 2: 批量复制项目书签
- **用户查询**: "把所有 project- 开头的书签复制到备份文件夹"
- **预期行为**:
  - Agent 创建"备份"文件夹
  - 使用 `cp project-* 备份` 批量复制
  - 验证原始书签仍保留，备份文件夹有副本

### 场景 3: 批量删除临时书签
- **用户查询**: "删除所有 temp- 开头的书签"
- **预期行为**:
  - Agent 使用 `rm temp-*` 批量删除
  - 验证所有 temp- 书签已被删除

### 场景 4: 通配符搜索
- **用户查询**: "找出所有 test- 开头的书签"
- **预期行为**:
  - Agent 使用 `find test-* -type f` 或 `ls test-*`
  - 列出所有匹配的书签

### 场景 5: 复杂通配符操作
- **用户查询**: "把所有 Vue 开头的书签移到前端框架文件夹，然后给它们加星标"
- **预期行为**:
  - Agent 执行多步操作
  - 使用通配符移动书签
  - 使用通配符批量加星标

### 场景 6: 通配符过滤显示
- **用户查询**: "只显示 React 开头的书签"
- **预期行为**:
  - Agent 使用 `ls React-*` 过滤显示
  - 只列出匹配的书签

## 验证要点

每个场景都会验证：

1. **命令执行**: Agent 是否正确使用了通配符命令
2. **结果正确性**: 操作是否达到预期效果
3. **数据完整性**: 数据是否正确移动/复制/删除
4. **响应质量**: Agent 的回复是否清晰准确

## 通配符功能优势

通过这些测试可以看到通配符功能的优势：

### 之前（无通配符）
```bash
# 需要多次调用 LLM，每个书签一条命令
mv "React-Official-Docs" 前端框架
mv "React-Router-Guide" 前端框架
mv "React-Redux-Tutorial" 前端框架
mv "React-Next.js-Framework" 前端框架
# 4 个书签 = 4 次 LLM 调用 + 4 次命令执行
```

### 现在（有通配符）
```bash
# 一次 LLM 调用，一条命令搞定
mv React-* 前端框架
# 4 个书签 = 1 次 LLM 调用 + 1 次命令执行
```

**效率提升**:
- LLM 调用次数: 减少 75%
- 命令执行次数: 减少 75%
- API 成本: 减少 75%
- 执行时间: 减少 ~80%

## 故障排查

### API Key 余额不足
```
Error: AI API 请求失败: 429 - {"error":{"code":"1113","message":"余额不足或无可用资源包,请充值。"}}
```

**解决方案**: 
1. 充值 API Key
2. 或使用其他 AI 服务商的 API Key
3. 更新 `.kiro/specs/key.md` 中的配置

### 网络连接问题
```
Error: 网络请求失败，请检查：1) 网络连接 2) API 地址是否正确 3) API 服务是否可用
```

**解决方案**:
1. 检查网络连接
2. 验证 API endpoint 是否正确
3. 确认 API 服务是否可用

### Agent 未使用通配符
如果 Agent 没有使用通配符命令，可能的原因：

1. **System Prompt 不够明确**: 检查 `prompts.ts` 中的系统提示
2. **示例不够清晰**: 在 help 命令中添加更多通配符示例
3. **LLM 模型限制**: 某些模型可能不理解通配符概念
